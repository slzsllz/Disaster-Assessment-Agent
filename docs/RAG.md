# 共享规则知识库

## 使用

1. 启动后端和前端，在左侧点击“添加规则文档”。管理页地址为 `/rules`，刷新不会跳回聊天页。
2. 可填写发布单位、版本、生效日期、适用地区和灾害类型，再上传 PDF 或 `.docx`，支持批量选择。
3. 等待状态变为“可检索”。后台依次解析、分块、调用 Embedding 接口，然后一次性发布索引。
4. 可在页面下方先试查规则，也可回到聊天中提问，例如：“依据知识库中的防汛预案，结合本次洪水检测结果说明应急处置要求，并引用原文。”
5. 回答中的规则引用对应真实文档片段；展开“规则依据”可查看页码/段落、原文和来源。引用快照保存进消息表，读取历史不会丢失。

知识库不仅支持规则，还支持灾情评估报告、案例和研究资料，不限制国内事件。
询问灾害事件、已上传报告或规则时，Agent 应先查知识库，再考虑网页搜索；纯检测、
闲聊和实时天气查询不强制检索。报告内容应注明来自上传文档，不自动当作实时新闻或
官方结论。工具计算的面积和像素数不由规则文档替代；没有命中文档时，不应声称已核实某项地方标准。

## 配置

附加解析依赖：

```bash
python -m pip install -r requirements-rag.txt
```

环境变量示例见根目录 `.env.rag.example`。在现有根目录 `.env` 中加入所需配置，随后重启后端：

```dotenv
RAG_EMBEDDING_BASE_URL=https://你的工作空间.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
RAG_EMBEDDING_API_KEY=具有向量模型权限和额度的密钥
RAG_EMBEDDING_MODEL=qwen3.7-text-embedding-flash
RAG_EMBEDDING_DIMENSIONS=1024
RAG_MIN_SCORE=0.35
RAG_RECALL_K=20
RAG_RERANK_MODEL=qwen3-rerank
```

当没有显式设置独立向量接口时，后端可复用当前官方阿里云聊天配置的地址和密钥；第三方聊天网关不会被自动当作向量接口。显式设置独立地址后，必须同时设置对应密钥，避免把聊天密钥发送到另一个服务。

聊天权限与向量模型权限/额度是两回事。`insufficient_quota` 表示向量模型额度或付费权限不足；HTTP 401/403 也可能与密钥、模型授权有关。失败会显示在文档行中；解决配置或额度问题后点击“重试 / 重建索引”。不会生成假向量或把失败任务标记为成功。

模型、接口地址或维度变化后，旧文档显示“需要重建索引”，在重建前不参与新配置的检索，避免混用向量空间。

默认向量模型为 `qwen3.7-text-embedding-flash`，维度保持 1024，使用现有百炼
OpenAI 兼容接口；主聊天模型、重排序模型和证据核验模型不随之切换。
原先使用 `text-embedding-v4` 的文档需要在后端重启后点击“重试 / 重建索引”，
无需重新上传原文件。即使新旧模型均为 1024 维，也不能混合其向量。
若当前没有可用索引，或已检索部分不足以回答且仍有未重建文档，接口返回
`status=unavailable, reason=index_needs_rebuild`，明确说明文档仍在库中，
不能将模型切换后的旧索引误报为“没有相关文档”。已有新索引能提供充分证据时，
不因其他旧文档未重建而阻止正常回答。停用文档和不符合地区/类型筛选的文档不计入该提示。

## 存储与任务

- 当前是项目级共享库，没有用户归属，也不使用 localStorage。
- 原文件保存在 `data/knowledge/`，可通过 `RAG_STORAGE_DIR` 指定持久目录。Docker 已挂载 `/app/data`。
- 新增 PostgreSQL 表 `knowledge_documents`、`knowledge_chunks`；按需创建，不删除或重写已有聊天记录。
- 文档行持久化保存排队状态及任务租约。后台进程重启后继续处理排队任务，处理中断的任务在租约到期后重新执行。多个后端进程通过行锁和租约避免同时发布同一任务。
- 索引未全部生成前不会对外检索。禁用立即排除检索，删除同时移除原文和分块；已有历史引用保留原文快照，但删除后的原文下载链接失效。
- SHA-256 相同的文件不重复入库。不同版本可以作为不同文档上传；请停用已失效版本，生效日期等元数据供模型核对，不自动代替人工判断法规效力。

当前 PostgreSQL 未安装 pgvector，采用 `REAL[]` 存储真实远程 Embedding 的归一化向量，流式读取候选向量并执行精确余弦相似度 Top-K 检索。此实现适合初期中小规模库，不是关键词匹配，也没有 ANN 索引。向量数量很大时，应升级为 pgvector/专用向量引擎以降低查询开销。默认阈值 0.35 仅为可配置的检索过滤参数，不是可信度或已校准的相关性标准。

## 检索与证据核验

页面检索和 Agent 工具使用同一条必经链路：

1. 向量召回：从已启用、处理完成、向量模型匹配的文档中取候选片段；可按地区、灾害类型筛选。默认召回 20 个，可用 `RAG_RECALL_K` 设置为 1–24，实际不少于请求的最终数量。
2. 重排序：调用百炼 `qwen3-rerank`，根据“片段是否解答问题”重新排序，而不是仅按主题相似度排序。默认取重排后的前 5 个进入核验，`top_k` 支持 1–8。
3. 充分性核验：默认使用当前聊天模型，独立调用、温度为 0，只判断候选原文能否完整支持本次问题，不生成用户答案。核对地区、时间、单位、前提条件、问题各部分以及文档之间的冲突；一般文档阅读题不会仅因未填元数据而被拒绝。
4. 代码验证：仅接受严格 JSON 结果、合法候选 ID 和原文中确实存在的连续引文；截断输出、伪造引文或无法解析的结果不予放行。最终返回经过核验的片段和原文出处。

同一片段可以支持多条引文，代码逐条验证后按片段合并，不因合法的重复 ID 拒绝整批证据。
返回 `evidence_quote`（第一条引文）和 `evidence_quotes`（全部已验证引文）。对于模型多转义的
换行/制表符，仅在原始引文不匹配时规范化这些空白，规范化后仍须连续匹配原文；
不修改数字、事实或措辞，也不会忽略同一片段中夹带的伪造引文。

检索结果 `status` 的含义：

| 状态 | 含义 | 返回片段 |
|---|---|---|
| `sufficient` | 模型判断证据足以回答，且引用通过代码验证 | 仅返回获准片段 |
| `no_match` | 没有可检索文档或没有达到召回阈值的片段 | 空列表 |
| `insufficient` | 主题相关但不能回答，或条件缺失、范围不适用、证据冲突、只支持部分问题 | 空列表 |
| `unavailable` | 索引需要重建，或重排序/核验配置、权限、额度、网络、响应格式异常 | 空列表，不混用旧模型向量，也不退回未经核验的片段 |

Agent 被要求在证据不足时明确说明知识库不能支持该问题；可以继续提供工具测量结果或标注为通用知识的解释，但不能冒充已核实的规则。服务异常应说明“核验暂不可用”，而不是断言文档中没有答案。只有 `sufficient` 结果能形成新的规则引用。

聊天链路通过后端运行配置传递本轮原始问题和最近 4 条历史用户问题，每条历史问题
最多 800 字符，仅保留文字，不传附件二进制或先前模型回答。Agent 应结合会话生成
独立完整的 `query` 用于向量召回。多轮重排序和核验收到的是结构化上下文：当前问题、
检索意图、之前的用户问题；当前问题的明确要求优先，历史只用于消解指代，不是事实证据，
也不要求片段回答所有历史问题。单轮核验继续使用完整原始问题，不能用 Agent 的压缩查询
代替它。运行配置不暴露为模型可填写的工具参数，页面检索继续直接使用页面输入的问题。

例如先问“你知道委内瑞拉地震情况吗”，再问“RAG库里不是有吗”，核验应理解为查询
该地震的已上传报告，而不是要求报告包含“RAG库里不是有吗”这句话。若追问已转到
其他灾害，则按新问题判断，不能用上一主题的报告强行作答。无依据、范围不适用、伪造引用
和服务异常的拒绝行为不变，相似度阈值不因该修复而降低。

后端首次恢复一个会话时，从数据库读取最近 40 条用户/助手文字消息，按时间顺序恢复，
不读取附件或图片二进制，避免后端重启后多轮指代断开。此恢复不重写已有聊天数据，
也不需要数据库迁移；并不重新构建历史图片的多模态输入。

“读取文档中的代号/清单”和“把文档当作正式应急规范”是不同任务：测试文档及空白可选元数据不妨碍前者；后者仍需正式来源、适用范围等依据。`insufficient` 表示已有候选未获核验通过，不代表文件不存在或未上传，不能向用户作此推断。

重排序默认从现有官方阿里云 Embedding 地址推导同地域的 DashScope 接口，并复用其密钥，不会跨地域自动切换。可分别配置 `RAG_RERANK_URL`（完整地址）、`RAG_RERANK_API_KEY`、`RAG_RERANK_MODEL`。第三方或独立接口需要显式设置对应地址和密钥。核验模型可用 `RAG_JUDGE_BASE_URL`、`RAG_JUDGE_API_KEY`、`RAG_JUDGE_MODEL` 独立配置；显式指定新地址时不会自动发送原聊天密钥。修改配置后重启后端即可，现有文档不需要重新向量化。

每次命中候选的检索通常增加一次重排序和一次文本模型调用，带来额外延迟和费用。没有候选时不会执行后两步。重排序分数是相关性排序分数，不是正确概率，不能与向量相似度混用。核验仍是模型判断，精确引文检查也不能证明原文本身正确，不能承诺零误判；应使用实际正例、近似负例、多条件问题和区域冲突样例持续评测，并核对重要应急决策的原始规范。

## 格式限制

- 单文件最多 20 MB；PDF 最多 1000 页；最多 200 万文字、4000 个分块。
- 文本 PDF 保留真实页码。完全没有可提取文字的扫描版 PDF 标记“需要 OCR”，当前不提供 OCR。部分扫描页不会被自动识别，应先对整份文件做 OCR。
- Word 支持 `.docx` 正文与表格，引用使用段落/表格位置，不伪造页码；旧版 `.doc` 需先转换。图片内文字、复杂版式或特殊公式可能无法完整解析，请核查文本预览与原文。
- 长条款可能需要拆分检索；应用阈值前应核对完整原文、适用地区、时间、单位和前置条件。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/knowledge/status` | 共享库和向量配置状态（不包含密钥） |
| `GET /api/knowledge/documents` | 文档列表与处理状态 |
| `POST /api/knowledge/documents` | 上传文档，multipart 字段为 `file` |
| `GET /api/knowledge/documents/{id}` | 元数据与前五个分块预览 |
| `PATCH /api/knowledge/documents/{id}` | 启用/停用，JSON 字段 `enabled` |
| `POST /api/knowledge/documents/{id}/retry` | 重试或重建索引 |
| `DELETE /api/knowledge/documents/{id}` | 删除文档和分块 |
| `GET /api/knowledge/documents/{id}/file` | 下载原文 |
| `POST /api/knowledge/search` | 检索，JSON 字段 `query`、可选 `top_k`、`region`、`disaster_type` |

FastAPI Agent 在 MCP 工具之外注册 `search_rule_documents`，由同一主智能体按需调用；二次多模态 review 复用已引用的规则证据，不代替主体分析。普通与 SSE 聊天接口均返回 `retrieval_refs`，历史消息保存在同名 JSONB 字段。

## 验证与部署

```bash
# 单元测试；数据库集成测试默认跳过
python -m unittest discover -s tests -p 'test_knowledge.py' -v

# 在独立临时 schema 中运行真实 PostgreSQL 集成测试，结束后清理测试 schema
RAG_TEST_DB=1 python -m unittest discover -s tests -p 'test_knowledge.py' -v

# 重排序、严格核验和拒绝路径单元测试（模拟外部服务，不消耗额度）
python -m unittest discover -s tests -p 'test_rag_verification.py' -v
```

测试中的固定向量仅用于隔离外部 API；正式服务始终使用远程 Embedding。应另用有可用额度的真实接口验证文档入库、规则检索和聊天引用。

当前系统没有登录权限控制。所有访问者共用知识库，文档管理接口不应直接暴露公网；公网部署需要网关访问控制或后端鉴权，并评估规则文档传往远程 Embedding 服务的数据合规性。当前 CORS 白名单不是鉴权。

接口参考：[阿里云 Embedding 文档](https://www.alibabacloud.com/help/en/model-studio/text-embedding-synchronous-api)、[阿里云重排序文档](https://help.aliyun.com/zh/model-studio/text-rerank-api)。
