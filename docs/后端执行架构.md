# 后端对话执行架构

`backend_api.py` 的两个对话接口共用 `ChatTurnService`。接口负责接收 HTTP 表单和选择响应形式；服务负责一轮对话的状态变化：

1. `start`：保存用户消息和上传文件，准备会话 Agent。
2. `prepare`：检索参考资料，按需强制联网搜索，构造模型消息。
3. Agent 执行：普通接口使用 `invoke`；流式接口通过 `iter_chat_events` 转发状态和草稿。
4. `finalize`：提取产物、审核结论、保存评估和助手消息，生成统一的 `TurnOutcome`。
5. `generate_report`：仅在用户要求且审核状态允许时生成 PDF。
6. `error_response` / `cancel_if_unfinished`：把失败或中断写入轮次状态。

`TurnOutcome.payload` 是两个接口共同使用的最终响应内容。SSE 额外发送 `status`、`delta` 和可选的 `report` 事件。添加新的审核或产物字段时，应先修改 `finalize`，避免两个接口出现不同结果。

`agent/review.py` 把所有工具共用的数值范围检查与灾种专用检查分开。新增灾种统计规则时，实现与现有函数相同签名的校验函数，并加入 `TOOL_METRIC_VALIDATORS`；严重问题返回 `critical`，由审核流程阻止发布结论。

验证命令：

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

当前测试覆盖两个对话接口的结果一致性、审核阻断、流式失败收尾，以及建筑损毁和洪水统计规则。实际模型、MCP 工具和数据库仍需在部署环境中做端到端验证。
