# 数据库与产物持久化

后端启动时按文件名顺序执行 `migrations/*.sql`，已执行版本记录在
`schema_migrations`。数据库不可用或迁移失败时，服务不会开始接收请求。
迁移文件也支持在现有数据库上执行；部署新环境时需要 PostgreSQL 和 PostGIS。

## 数据流

1. 请求到达后创建或更新 `sessions`，上传文件写入 `data/artifacts/<session_id>/`，
   其元数据写入 `artifacts`。
2. `start_turn` 在同一事务中写入用户消息与 `running` 轮次。
3. 工具成功后，每个工具结果写入 `assessment_results`，其 `artifact_ids` 指向
   持久化文件。GeoTIFF 的空间范围另存入 PostGIS `geom`。
4. `complete_turn` 在同一事务中写入助手消息并把轮次改为 `completed`。
   执行失败时 `fail_turn` 写入失败消息、状态和错误码，并删除该轮已写入的部分评估。
5. 新工作进程首次使用某会话时，从 `chat_messages` 和 `artifacts` 恢复 Agent 的
   多轮上下文。文件 URL 直接根据 `artifacts.id` 查询，不依赖进程内映射。

`data/artifacts` 必须放在持久化且所有后端工作进程可访问的卷上。数据库保存文件
元数据与校验值；新文件的二进制内容不再编码进聊天 JSONB。会话删除或清空时，
对应数据库记录与文件目录一并清理。

## 检索增强

`retrieval_embeddings` 保存已接入工具说明及会话文件元数据的文本向量，使用
`source_type/source_id` 标识来源，并用 `session_id` 隔离文件。模型与内容哈希
变化时重新计算向量。当前语料规模较小，向量用 PostgreSQL `real[]` 保存并在
Python 中计算相似度；无需 `pgvector`。向量化请求发送到配置的
`EMBED_SERVER_URL` 的 `POST /embed`，服务不可达时退回关键词检索。
检索命中的来源保存在助手消息的 `retrieval_refs` 字段，历史会话可以恢复引用。
清空或删除会话时，同时清理该会话的文件向量。

## 历史数据迁移

旧消息中的内嵌文件可以迁移到统一产物目录：

```bash
python scripts/migrate_legacy_artifacts.py
python scripts/migrate_legacy_artifacts.py --apply
```

第一条命令只统计，第二条命令复制文件、校验 SHA-256、更新消息引用并清除旧的
JSONB 内嵌文件内容。脚本可重复运行。若历史记录只剩路径且原文件已经不存在，
引用会标为 `unavailable`；这类文件无法凭数据库中的路径恢复。

## 状态与排障

- `GET /api/sessions/{session_id}/turns` 返回 `running/completed/failed` 状态。
- `GET /api/sessions/{session_id}/assessments` 返回工具结果及产物下载链接。
- 后端启动时将超过一小时仍为 `running` 的轮次标记为中断，并留下历史消息。
- 数据库中断时，新请求返回 503；执行中的请求会明确报告保存失败。

当前接口沿用既有会话 ID 访问模式。若服务开放给不受信任的用户，还需要增加
身份认证和按用户过滤会话、评估及文件下载权限。
