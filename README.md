# 城市灾害与韧性评估智能体

Disaster Assessment Agent 是面向城市安全与智慧应急场景的应用型智能体。系统通过自然语言交互，将灾害检测模型、遥感分析、地理上下文、天气查询和知识库检索连接起来，为灾情分析与灾后恢复提供有依据的辅助研判。

项目采用前后端分离架构，以单个 Agent 调用多个工具完成任务，并非多智能体协同系统。

## 主要功能

- **灾害检测**：支持地震建筑损毁、洪水淹没、山火烧毁区变化、滑坡、海面溢油、农业受害目标、候选藻华，以及城市火焰烟雾检测和交通事故视频分析。
- **遥感分析**：提供光谱指数计算、栅格统计、变化分析及基础图像处理工具。
- **地理与天气辅助研判**：按需查询周边设施和天气预报，国内地理上下文使用高德，国外使用 ArcGIS；支持国内应急候选路线规划。
- **RAG 知识库**：上传 Word/PDF 文档，完成文本解析、分块和向量索引；检索结合重排序与证据充分性核验，为回答提供可引用的依据。
- **多模态复核**：对可读取的输入图片和工具输出进行复核，选择适合展示的图片及可下载文件，补充文件用途和下一步建议。
- **错误经验**：记录工具调用错误及修复经验，通过错误匹配和向量检索辅助后续调用恢复。
- **交互与历史记录**：提供流式回答、附件上传、历史对话、地图抽屉和结果下载；历史会话通过后端访问数据库，不依赖浏览器 localStorage。

## 工作流程

```text
用户提出问题，并按需上传影像或资料
    -> Agent 结合当前会话、系统提示词理解任务
    -> 按需调用检测、地理、天气、检索等工具
    -> 工具返回量化指标、可靠性说明和产物路径
    -> Agent 生成主体分析与结论
    -> 有相关产物时，进行二次多模态 review 和文件选择
    -> 前端展示回答、选定图片、文件说明及下载入口
```

工具间通过真实文件路径传递数据。主体回答使用 `<Conclusion>` 标记；review 使用 `<Artifacts>` 声明展示和下载选择，这些内部标记不作为正文展示给用户。

## 典型输入

不同工具的数据要求不同，不能将任意图片用于所有检测任务。

| 任务 | 主要输入要求 |
| --- | --- |
| 地震建筑损毁 | 同一区域、空间对齐的灾前与灾后 RGB 影像 |
| 洪水淹没 | 符合模型预处理要求的 Sentinel-1 VV/VH SAR 影像 |
| 山火变化检测 | 符合 FLOGA 模型要求的灾前、灾后多波段数据 |
| 滑坡分割 | Landslide4Sense 格式 HDF5，`img` 为 `128 × 128 × 14` |
| 海面溢油、农业受害目标 | 符合对应模型要求的 RGB 图像 |
| 候选藻华 | 七波段 GeoTIFF，顺序为 B2、B3、B4、B5、B8、B11、B12 |
| 城市火焰烟雾 | RGB JPEG/PNG 图片 |
| 交通事故分析 | 支持的视频，或符合工具约定的预提取特征文件 |

多时相数据应明确采集时间和先后关系。只有包含有效地理参考的数据，才能据此提取覆盖范围并在地图上定位；普通图片不能直接提供可信经纬度。

## 技术架构

| 层级 | 技术与职责 |
| --- | --- |
| 前端 | Vue 3、Vite、Element Plus，负责聊天、附件、知识库和地图交互 |
| 后端 | FastAPI，提供聊天、SSE 流式输出、会话及文件访问等接口 |
| Agent | LangChain / LangGraph，连接 OpenAI 兼容接口的大模型；当前主要配置为千问 |
| 工具 | FastMCP / MCP 子进程，封装检测模型和外部服务 |
| 存储 | PostgreSQL / PostGIS 保存业务数据；本地文件系统保存上传文件和产物 |
| 知识检索 | 文本向量模型、重排序和证据核验；默认向量模型为 `qwen3.7-text-embedding-flash` |

## 配置与启动

### 运行准备

1. 准备 Python 环境与模型依赖，可参考 `docker/environment.yml`；RAG 补充依赖见 `requirements-rag.txt`。不同模型还可能需要各自的推理依赖。
2. 将需要使用的模型包和权重放入 `model/`，检查工具配置中的路径。模型目录和密钥配置可能被 Git 忽略，拉取代码不等于已具备全部运行资源。
3. 配置大模型接口、数据库和所需外部 API。后端默认优先读取 `agent/config_qwen3.json`，也可通过 `AGENT_CONFIG` 指定配置文件。
4. 后端环境变量放在根目录 `.env`；RAG 配置可参考 `.env.rag.example`。前端地图配置放在 `frontend/chatDisaster/.env.local`，涉及 `VITE_ARCGIS_API_KEY` 等变量。
5. 若需要历史对话与知识库功能，应确保数据库服务、所需表结构及相关服务配置可用。缺少某项 API 配置时，不代表对应功能能够正常运行。

不要将真实密钥或包含密钥的配置提交到仓库。前端 `VITE_*` 配置会进入浏览器，应设置相应的来源限制与最小权限。

### 启动后端

在项目根目录、已配置依赖的 Python 环境中执行：

```bash
conda activate earthagent_cpython
python -m uvicorn backend_api:app --host 0.0.0.0 --port 8000
```

后端健康检查：`http://127.0.0.1:8000/api/health`；接口文档：`http://127.0.0.1:8000/docs`。

### 启动前端

在另一个终端执行：

```bash
cd frontend/chatDisaster
npm install
npm run dev -- --host 0.0.0.0
```

开发服务器默认使用 `5173` 端口，以终端实际输出为准；Vite 将 `/api` 请求代理至本机 `8000` 端口。生产构建使用 `npm run build`。

在各自终端按 `Ctrl+C` 停止服务。进一步说明见 [API 使用说明](API_USAGE.md)、[Docker 部署说明](DOCKER_DEPLOY.md)、[地理上下文说明](docs/GEO_CONTEXT.md) 和 [评测说明](evaluation/README.md)。部署前应核对部署文档中的模型目录、初始化脚本与当前分支实际文件是否一致。

## 能力边界

- 系统用于辅助分析，不替代官方预警、现场核查、建筑安全鉴定或应急指挥。
- 洪水掩膜不代表水深；周边设施不代表已受灾；候选路线不代表已验证安全通行。
- 建筑损毁掩膜的像素数不是建筑栋数；农业受害目标不是虫子数量；NDCI 候选藻华不等于有毒赤潮。
- 当前天气工具提供当前天气和未来预报，不提供历史天气或官方预警。
- 检测结果受模型、输入质量、分辨率和适用场景限制；知识库证据不足时，应说明缺少依据，而非编造结论或引用。
